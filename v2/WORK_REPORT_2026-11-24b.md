## 2. 왜 이렇게 짰나
- **한 원본에서 두 문서를 만든다.** 2.36.1 PDF의 생성기가 저장소에 없어 PDF를 다시 만들 수 없었고, README와 PDF가 따로 낡았다(README의 "증거 규칙 37개" 같은 틀린 수치가 남았다). 글을 `overview_content.py`의 블록(문단, 목록, 표, 흐름 상자, 코드)으로 한 번만 쓰고, 생성기가 GitHub Markdown과 PDF로 그린다. 시험 `test_overview_docs.py`가 커밋된 README가 원본의 렌더링과 같은지 확인하므로 README만 손으로 고치면 시험이 깨진다.
- **ReportLab을 골랐다.** 옛 PDF도 ReportLab으로 만들어졌고(`pdfinfo` Producer), 순수 파이썬 패키지 하나면 되고, `invariant` 모드로 생성 시각 없이 같은 파일이 나온다. 버린 대안: Pandoc + LaTeX(시스템 패키지가 크고 사용자 PC에서 다시 만들기 어렵다), 헤드리스 Chromium 인쇄(무겁고 글꼴·쪽 나눔이 환경마다 다르다).
- **글꼴과 글리프.** 영어라 CJK 글꼴 문제는 없다. 그래도 ′ ″ ≥ ≤ σ ° − × ▼ 같은 기호가 있어 DejaVu Sans를 쓰고, 생성기가 본문의 모든 문자를 글꼴에서 찾아 빠진 글자가 있으면 빈 상자를 찍는 대신 목록과 함께 멈춘다(`test_pdf_builds_with_all_glyphs`). 글꼴은 `$OVERVIEW_FONT_DIR`, matplotlib 번들, 시스템 폴더 순으로 찾는다.
- **수치는 파일에서 다시 확인했다.** 옛 README·PDF에서 가져오지 않고 eab50c6의 CHANGELOG, `ALGORITHM.md`, `STATUS_2026-11-12.md`, `LOCKED_TEST_SET_C.md`, 작업 보고서, 코드에서 읽었고 문서 끝 "Where the numbers come from" 표에 출처를 적었다. 수집기 수(30), 증거 규칙 수(35), 요약 열 수(29)는 시험이 코드와 비교한다.
- **한계를 숨기지 않는 구성.** 1차 분류는 "전 파장"이 아니라 광학 색·형태, WISE, Gaia 천체측정·DSC가 정한다고 쓰고(끄기 시험 표를 넣음), X선·전파는 기여 0으로 적었다. 성능은 표본마다 주의점을 같은 칸에 적었다(세트 C는 별 95 %, 옛 SDSS 벤치마크는 대표성 없음, 세트 A/B는 개발 세트). 7·8·11절이 그 내용이다.

## 5. 릴리스 노트 (제안과 구현)
- 원인: 빌드 워크플로가 `## <버전>` 제목을 찾지만 CHANGELOG는 표(`| 버전 | 날짜 | PR | 요약 |`)라서, 릴리스 본문이 늘 "See v2/CHANGELOG.md"로 떨어졌다(v2.60.2도 그렇다).
- 고침(작고 그 안에서 끝남): `release_notes.py VERSION`이 `## <버전>` 제목이 있으면 그 절을, 없으면 표의 그 버전 행을 본문으로 만든다(제목, 날짜·PR, 요약, 전체 이력과 영어 README 링크). 요약 칸 안의 `\|`는 복원하고 칸을 자르지 않는다. 없는 버전은 빈 문자열이라 워크플로의 기존 대체 문구가 그대로 쓰인다. 시험 5개(`test_release_notes.py`)에는 현재 `v2/VERSION`의 행이 있어야 한다는 검사도 있어서, CHANGELOG 행을 빠뜨리면 병합 전에 시험이 막는다. 지난 릴리스는 건드리지 않았다. 본문은 CHANGELOG 언어(한국어)다.
- 워크플로 자체(`gh release create`)는 이 환경에서 돌릴 수 없어, 스크립트와 시험까지만 확인했다. 다음 릴리스에서 처음 쓰인다.

## 6. PDF 렌더링 확인 방법
- `pdftoppm -r 90`으로 9쪽을 모두 그림으로 만들어 쪽마다 확인했다(두 차례: 처음 빌드, 고친 뒤).
- 처음 빌드에서 찾아 고친 것: 코드 블록 한 줄이 오른쪽 여백을 넘었고(줄을 나눔), 표 앞 제목이 표를 통째로 다음 쪽으로 밀어 쪽 아래가 크게 비었고(제목 앞에서 남은 공간을 보고 쪽을 나누도록 바꿈), ≥ ≤ ′ ″ ° σ를 ASCII로 쓴 곳이 있었다.
- `pdffonts`로 글꼴 포함 확인(DejaVu Sans, Bold, Mono), `pdftotext`로 ′ ≥ ≤ σ ° − × – ▼ •가 본문에서 그대로 추출됨을 확인했다. ″는 ACS 반경(1.0″)에 쓰였고 시험이 PDF 본문에서 찾는다.
