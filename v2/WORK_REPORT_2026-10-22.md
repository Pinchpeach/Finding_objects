# 작업 보고서 2026-10-22 — 분광 분류 확장, 빠진 아카이브 경고, 실제 하늘 순도, 고신뢰 표시 (2.36.0)

- **무엇을 했나:** 네 가지를 했다.
  1. DESI DR1과 LAMOST DR5의 분광 분류를 1차 분류 증거로 쓴다. 지금까지는 SDSS 분광만 증거였다.
  2. 조회에 실패한 아카이브를 결과에 남기고 앱에 경고로 보여 준다.
  3. 실제 하늘의 종류 비율 기준으로 순도·완전도표를 만들었다.
  4. 고신뢰 기준을 만들어, 검색 영역에서 믿을 만한 천체를 따로 보고(필터) 하늘 지도에서 금색 테두리로 표시한다.
- **결과:**

  | 항목 | 값 |
  |---|---|
  | 벤치마크 | SDSS 98.69 %, DESI 92.41 % (같음, 예측 변화 0) |
  | 고신뢰 표시된 독립 정답 천체 | 1,728개 중 1,482개, **정확도 99.73 %** (표시 안 된 나머지 82.1 %) |
  | 18개 영역의 고신뢰 비율 | 전체 천체의 66 % (은하 197,199, 별 19,489, QSO 0) |
  | 실제 하늘 QSO 순도 (측광, 확신도 ≥ 0.9) | **6.4 %** — 검증 표본에서 본 81 %보다 크게 낮다 |

## 1. 분광 분류 증거 (DESI, LAMOST)

### 왜 이제까지 안 썼나, 왜 지금 쓰나
- DESI 분광은 DESI 정답 세트를 만든 바로 그 자료다. 그래서 2.11.0부터 "독립 확인용"으로만 남겨 두었다.
- 하지만 벤치마크 특징 파일(`benchmark/*/catalog_features`)에는 분광 수집기가 아예 없다. 그래서 분광 규칙을 더해도 벤치마크 정답이 새어 들어가지 않는다. 실제로 두 벤치마크 예측이 하나도 바뀌지 않았다.
- 독립 검증(2.35.0)의 blind 모드도 분광 목록을 빼고 돌리므로 그대로 독립 수치다.
- 실제 검색에서는 받은 분광을 버릴 이유가 없다. 좋은 분광 분류는 어떤 측광 증거보다 확실하다.

### 기준 (문헌)
- **DESI:** Redrock SPECTYPE을 쓴다.
  - ZWARN = 0 이고 DELTACHI2 ≥ 25이면 신뢰도 1.0이다. DR1의 신뢰 적색이동 기준으로, 최적 주형이 다음 주형보다 약 5σ 낫다는 뜻이다.
  - 그 밖의 분광은 0.5다.
  - backup 프로그램의 GALAXY 판정은 대부분 잘못 맞춘 어두운 별(약 65 %)이라서 0.5만 준다.
- **LAMOST:** 1D 파이프라인 class를 쓴다.
  - g 또는 i 밴드 S/N > 10이면 좋은 품질이다(Luo et al. 2015).
  - 18개 영역에서 다른 탐사와 대조했다. S/N ≥ 10에서 44/45, 그 아래에서 16/18이 일치했다(Unknown 제외). 그래서 S/N ≥ 10은 1.0, 그 아래는 0.5로 했다.
  - "Unknown"은 증거를 내지 않는다.

### 구조 선택
- SDSS 분광과 같은 방식인 `catalog_label` 사전 가중치(1.5 × logit)로 넣었다. 융합 재학습이 필요 없다.
- **버린 대안:** "좋은 분광이면 무조건 그 종류" 같은 결정 규칙. 연관이 틀린 경우(이웃 천체의 분광)에도 분광이 이기는데, 그때 측광 증거가 아주 강하면 그쪽이 이기는 편이 안전하다고 봤다.
- **측정 (full 모드, 근사 재융합):**
  - 다른 탐사가 정답이면서 LAMOST 분광도 있는 천체는 5개뿐이다. 1개 고침, 0개 나빠짐.
  - LAMOST가 정답인 천체에서는 97.95 → 99.73 %다. 순환 검사라서 성능 수치가 아니라, 분광이 있으면 분류가 분광을 따른다는 확인이다.

## 2. 빠진 아카이브 경고

### 왜
- 2.35.0 검증에서 결과가 나쁜 영역의 주 원인은 아카이브 접속 실패였다. Legacy Surveys가 없으면 미분류가 39–68 %였다.
- 그런데 결과 파일에는 아무 표시가 없었고, 앱도 상태 표시줄에 잠깐 보여 줄 뿐이었다.

### 어떻게
- `catalog_coverage.py`가 수집 요약(`collection_summary_*.csv`)에서 error/timeout인 수집기를 찾는다. 각 수집기가 빠지면 분류가 무엇을 잃는지 함께 적는다(`IMPACT`).
- 결과는 `catalog_coverage.json`으로 저장하고, 앱 결과 표 위에 노란 띠로 계속 보여 준다.
- **핵심 아카이브:** 대부분의 천체가 기대는 증거를 주는 Gaia, PS1, Legacy Surveys, AllWISE다. 이 중 하나라도 빠지면 "분류가 덜 확실할 수 있음"이라고 쓰고, 고신뢰 판정의 측광 경로를 막는다. 고신뢰 임계값이 이 자료가 있는 상태에서 측정된 것이기 때문이다.
- **버린 대안:** 천체마다 경고 열을 다는 것. 실패는 영역 단위이고, 천체마다 반복하면 표만 무거워진다.
- 수집 요약이 없는 경우(다른 곳에서 모은 파일을 분류)는 "모름"(`known: false`)으로 둔다. "문제 없음"으로 착각하지 않게 하려는 것이다.

## 3. 실제 하늘 순도와 확신도 기준표

### 문제
- 검증 표본은 하늘이 아니다.
  - DESI 시험 세트는 밝기 구간마다 세 종류를 같은 수로 뽑았다.
  - 독립 탐사는 별(LAMOST·RAVE), 방출선 은하(WiggleZ), 자외선 초과 퀘이사(2QZ)를 골라 관측했다.
- 표본에서 잰 순도는 표본의 비율을 반영할 뿐이다. 어두운 하늘에서는 은하가 퀘이사보다 약 100배 많다.

### 방법 (`benchmark/natural_purity.py`)
1. **재현 행렬:** R_b(t) = P(예측 c, 확신도 ≥ t | 실제 종류, 밝기 구간 b). 종류 비율과 무관하므로 표본에서 잴 수 있다.
   - 밝은 구간은 독립 정답, 어두운 구간은 DESI 시험 세트를 쓴다.
   - 밝기 구간은 r ≤ 18, 18–20, 20–21, 21–22, > 22다.
2. **영역의 실제 개수:**
   - 퀘이사는 문헌 개수로 고정한다. g < 22.5까지 147개/deg²(Palanque-Delabrouille et al. 2016), r < 23까지 약 230개/deg²(DESI)다.
   - 별·은하는 18개 영역의 예측 개수에서 NNLS로 푼다.
3. **순도:** 베이즈 식 순도 = n_c R_cc / Σ_s n_s R_sc 로 계산한다.

### 설계 이유
- **퀘이사를 고정한 이유:** 처음에는 세 종류를 모두 자유롭게 풀었다. 그러자 은하 2–5 %의 오분류만으로 QSO 예측을 모두 설명할 수 있어서 퀘이사 비율이 0으로 갔다. 자료로 정할 수 없는 값이라 문헌에서 가져왔다.
- **Jeffreys 추정 (k + ½)/(n + 1):** 표본에서 한 번도 안 본 오분류를 0으로 두면, 확신도 0.999 QSO의 순도가 100 %로 나왔다. 실제로는 은하 175개 중 0개라는 뜻일 뿐이다. 은하가 75배 많은 구간에서는 0.5 %만 새어도 순도가 60 %대로 떨어진다.
- **불확실성:** 정답 천체를 (구간, 종류)별로 200번 부트스트랩했다.

### 결과 (blind, 영역 전체, 실제 하늘 기준)

| 종류 | 확신도 ≥ 0.5 | ≥ 0.8 | ≥ 0.9 | ≥ 0.99 |
|---|---|---|---|---|
| 별 | 75.5 % | 97.6 % | 97.6 % | 97.6 % |
| 은하 | 98.8 % | 99.2 % | 99.5 % | 99.2 % |
| QSO | 4.1 % | 5.7 % | 6.4 % | 6.6 % |

- **별:** 확신도 0.5에서 75 %인 것은 r > 22의 어두운 "별" 예측 탓이다. 그 구간 순도는 53 %이고, 확신도 0.8 이상이면 95 %다.
- **QSO:** 영역들의 측광 QSO 예측은 약 1,750개/deg²다. 문헌상 실제 퀘이사는 r < 23까지 약 230개/deg²이므로, 어떤 재현 모형을 써도 대부분이 가짜일 수밖에 없다. 2.35.0 보고서의 "QSO 순도 81 %"는 퀘이사가 많은 검증 표본 기준이었고, 실제 하늘 기준이 아니었다.
- **한계:**
  - 정답 표본이 각 구간·종류마다 수십–수백 개라서, 98 % 이상은 증명할 수 있어도 99.5 % 같은 값은 증명할 수 없다.
  - 표 값은 "예측이 같은 확신도인 천체들은 표본에서와 같은 비율로 틀린다"는 가정을 따른다. 표본의 선택 효과(색 선택 등)가 이 가정을 흔들 수 있다.

## 4. 고신뢰 기준과 하늘 지도 표시

### 기준 (`high_confidence.py`)
천체가 CLASSIFIED이고 아래 둘 중 하나면 고신뢰다.
- **분광 확인:** 같은 종류의 좋은 분광이 있다(SDSS zwarning 0, DESI ZWARN 0이고 Δχ² ≥ 25, LAMOST S/N ≥ 10). 분광의 연관 신뢰도는 0.8 이상이어야 한다.
- **측광:** 확신도가 (종류, 밝기 구간)별 임계값 이상이다. 임계값은 부트스트랩 16번째 백분위에서 실제 하늘 순도가 98 % 이상이 되는 가장 낮은 확신도이고, 그 구간의 정답이 20개 이상이어야 한다(`Classifier/high_confidence.json`).

  | 구간 | 별 | 은하 | QSO |
  |---|---|---|---|
  | r ≤ 18 | 0.5 | 0.5 | 없음 |
  | 18–20 | 0.5 | 0.5 | 없음 |
  | 20–21 | 0.7 | 없음 | 없음 |
  | 21–22 | 없음 | 0.5 | 없음 |
  | > 22 | 없음 | 0.5 | 없음 |

- 측광 QSO는 어느 구간에서도 98 %에 닿지 않는다. 퀘이사는 분광으로만 고신뢰가 된다.
- **98 %를 고른 이유:** 99 %로 하면 표본 크기 때문에(약 100개 구간의 Jeffreys 하한) 18–20 은하처럼 실제로는 오류가 거의 없는 구간까지 증명이 안 된다. 95 %는 "고신뢰"라 부르기 어렵다.
- **검증 (독립 정답, blind):**
  - 1,482개를 표시했고 99.73 %가 맞다.
  - 틀린 것은 4개다: 은하→별 1, QSO→은하 1, 별→은하 2.
  - 표시 안 된 246개의 정확도는 82.1 %다.

### 앱
- 하늘 지도에서 고신뢰 천체 아이콘 밑에 금색 고리를 그린다. "Highlight" 체크로 끌 수 있고, 범례에도 넣었다.
- 표 위에 "High confidence only" 필터를 두고, 개수 표시에 고신뢰 수를 더했다.
- 천체 상세에는 "★ high confidence: spectrum (DESI DR1)" 또는 "photometry (18-20, p >= 0.5, real-sky purity >= 99.9 %)"를 보여 준다.
- **고리를 고른 이유:** 아이콘 모양·색은 이미 종류·세부 종류를 뜻한다. 테두리는 그 정보를 가리지 않고 겹쳐 보일 수 있다. 아이콘보다 먼저(밑에) 그려 선택 표시와도 겹치지 않는다.
- 오프스크린으로 그려 확인했다. NGC 4522 영역(경고 띠, NGC 4522에 고리)과 Stripe 82 영역(은하 대부분 고리, 어두운 별·QSO는 고리 없음).

## 6. 속도
- 고신뢰·경고 계산은 열 연산과 JSON 한 번 읽기다. NGC 4522 영역(84개)의 전체 실행은 2.1 s로 같고, 천체 27,904개 영역(NGP 220)에서 0.10 s다(처음 행 단위 반복은 0.19 s여서 열 연산으로 바꿈).
- 실제 하늘 순도 스크립트(부트스트랩 200회)는 약 70 s 걸리고, 분류할 때가 아니라 기준표를 다시 만들 때만 돈다.

## 7. 남은 일
- QSO의 실제 하늘 순도가 낮다. 확신도에 실제 하늘 사전확률(밝기별 퀘이사 개수)을 넣으면 순도는 오르고 완전도는 내려간다. 사용 목적(찾기 vs 확실한 목록)에 따라 고를 수 있게 하는 것이 다음 후보다.
- 어두운 별(r > 21) 정답 표본이 작다. 더 크면 고신뢰 범위가 넓어진다.
