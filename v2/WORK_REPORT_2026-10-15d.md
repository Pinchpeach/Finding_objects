## 2. E — ZTF 변광
### 수집
- IRSA ZTF 광도곡선 API로 세 정답 세트(SDSS, DESI 외부, DESI 융합 학습)의 대응체를 모았다.
- 수집기(`Get_data/ztf_lightcurve.py`)는 천체마다 r(없으면 g) 밴드에서 다음을 계산한다.
  - 좋은 시기 수
  - 감소 χ²
  - 구조함수 진폭 A와 기울기 γ (Schmidt et al. 2010)
- **처음 시도(3 작업 × 32 동시 질의)는 실패**했다.
  - IRSA가 DESI 질의 전부와 SDSS·학습 세트 질의의 64–75 %에 `400 Bad Request`를 돌려줬다.
  - 일부 질의는 성공했으므로 요청 형식 문제는 아니었다. 오류가 1 %를 넘어 커밋 단계에서 모두 버려졌다.
- **고친 방법**
  - 수집 워크플로에 `shards` 입력을 넣어, 정답 세트를 6조각으로 나눠 18개 러너가 각각 4개씩 동시에 질의하게 했다.
  - 조각들은 커밋 단계에서 합친다. 모든 조각이 도착하고 전체 오류가 1 % 미만일 때만 반영한다.
  - IRSA 거절 응답의 본문을 오류 메시지에 남기고, 거절되면 더 길게 기다렸다가 다시 시도한다.
  - 결과: 오류 0건.
- **적용 범위** (10시기 이상인 광도곡선 비율)
  - SDSS 정답: 92–99 %
  - DESI 정답: 62–76 %

### 왜 채택하지 않았나
- **은하의 가짜 변광**
  - 처음에는 모든 천체에 특징을 냈다. 그러자 은하의 감소 χ² 중앙값이 SDSS에서 10.6이었다(QSO 3.7, 별 1.6).
  - 원인: 넓게 퍼진 천체의 PSF 측광은 시상(seeing)에 따라 달라져서 변광처럼 보인다.
  - Palanque-Delabrouille et al. 2011처럼 점광원(LS PSF 모델, 없으면 PS1 i PSF−Kron < 0.05)에만 쓰도록 바꿨다.
  - 시기 수와 등급은 탐사 특성이라 특징에서 뺐다.
- **후보 비교** (모두 D 세트 포함, 선택은 보정 분할로)

| 후보 | 보정 log-loss (선형 / 나무) | SDSS | DESI |
|---|---|---:|---:|
| ZTF 없음 (2.26.0) | 0.1433 / 0.1170 | 98.69 % | 92.52 % |
| ZTF 모든 천체, 나무 | 0.1606 / 0.1232 | 98.64 % | 92.31 % |
| ZTF 모든 천체, 선형 전용 | 0.1606 / 0.1183 | 98.74 % | 92.41 % |
| ZTF 점광원만, 나무 | 0.1473 / 0.1217 | 98.74 % | 92.41 % |
| ZTF 점광원만, 선형 전용 | 0.1473 / 0.1170 | 98.74 % | 92.41 % |

- **판단**
  - 가중치의 방향은 물리적으로 맞다(구조함수 기울기 γ → QSO +1.28).
  - 그러나 test 차이는 SDSS +1개, DESI −1개다. 보정 log-loss는 모든 후보에서 나빠졌다.
  - 실제 영역에서는 IRSA 광도곡선 질의가 영역마다 분 단위로 걸린다(벤치마크에서는 800개 천체에 72분, 4 동시 질의).
  - CLAUDE.md 규칙 2(정확도와 속도를 함께)에 따라 채택하지 않았다.
- **남겨 둔 것**
  - 수집기와 4단계 규칙 코드(`ZTF-VAR-001`, 규칙표에 행이 없으면 꺼져 있음), 수집한 벤치마크 특징.
  - 생산 수집 목록에는 넣지 않았다.
  - 효과가 있을 만한 경우: ZTF DR 다음 판이 시기 수를 늘리거나, Gaia 시차가 없는 어두운 점광원에서 별과 QSO를 구별해야 할 때.

## 3. 결과가 바뀌는 버그 수정
- **DSC-001**
  - Gaia DSC의 별·백색왜성·쌍성 확률이 모두 정확히 0이면(확신하는 은하·QSO) 증거를 내지 않았다.
  - 0을 처리하려고 둔 `DSC_FLOOR`가 쓰이지 않았다. 벤치마크 DSC 행의 41 %(3,563/8,769)가 여기에 해당했다.
  - 이제 합이 0이어도 증거를 내고, 0은 하한으로 처리한다.
  - 정확도는 거의 같다(SDSS 98.69 → 98.69 %, DESI 92.52 → 92.41 %). 이 천체들은 다른 증거로 이미 맞게 분류되고 있었다.
  - 보정 분할의 선형 log-loss는 0.1433 → 0.1427로 좋아졌고, 나무는 0.1170 → 0.1182로 나빠졌다.
  - 수정 이유: 정확성(의도된 동작).
- **SDSS CalciumWD (DZ 백색왜성)**
  - 세부 분류에서 백색왜성으로 인식되지 않아, Gaia 색으로 주계열 분광형("F5 V" 등)을 받을 수 있었다.
  - 이제 SDSS WD 템플릿 이름에 "WD"가 들어 있으면 모두 백색왜성으로 판정한다(WD, WDhotter, WDcooler, WDmagnetic, CarbonWD, CalciumWD).

## 4. 전체 코드 검수와 간결화
### 방법
- 4개 영역(수집, 전처리, 분류기, 앱·벤치마크)을 읽기 전용으로 먼저 검수했다.
- 결과는 다음 둘로 나눴다.
  - "구체적인 실패 경로가 있는 버그"
  - "결과가 같은 간결화"
- 간결화마다 수정 전후를 비교했다. 같지 않으면 적용하지 않았다.

| 영역 | 검증 |
|---|---|
| 수집 | 가짜 응답으로 137개 경우의 수집기 출력(열 순서·형식·오류 메시지·저장 CSV)을 이전 코드와 비교: 차이 0 |
| 전처리 | SDSS·DESI·학습 세트 전체 행의 2–5단계 출력, 01→05 전체 CLI 실행, 벤치마크 예측, 융합 재학습 결과(JSON과 나무 배열) 모두 바이트 단위로 같음 |
| 분류기 | 실제 15,130행 + 무작위 30,000행에서 모든 축·세부 분류 출력이 같음, 파이프라인 `classified_objects.csv` 같음, 속도 같음 |
| 앱·벤치마크 | coarse 벤치마크 출력이 같음, 앱 버그 수정은 화면 없이(offscreen) 실행해 확인 |

### 주요 간결화 (순 −858줄)
- **수집 (−417줄)**
  - VizieR 수집기 20여 개가 반복하던 질의·기본 열·저장 코드를 `_catalog_utils`의 도우미로 모았다.
  - Chandra·XMM·eROSITA는 한 함수(`id_cone`)를 공유하고, FIRST·NVSS의 같은 좌표 함수를 하나로 합쳤다.
- **전처리 (−170줄)**
  - 4단계 `evaluate()`의 반복 `emit`/특징 출력 코드를 `hit()`, `feature()`로 줄였다.
  - 5단계는 `fuse`와 `fuse_many`가 선형 결합을 공유한다(`_fuse_linear`). 혼합 융합에서 증거를 두 번 계산하던 것이 없어졌다.
  - 2단계에서 아무것도 바꿀 수 없던 복사 루프를 지웠다(증명을 주석으로 남김).
- **분류기 (−234줄)**
  - 태그·축 결과 사전을 도우미로 만들었다.
  - SIMBAD 지정 분기를 표로 바꿨다.
  - 6개 모듈이 각자 정의하던 `_num`·`_text`·SIMBAD otype 로더를 `_rowutil.py` 하나로 모았다(otype 표를 6번 읽던 것이 1번으로).
- **앱·벤치마크**: 메뉴·저장 항목·정보 라벨을 표로 바꾸고, 쓰이지 않는 정렬 역할을 지웠다.

### 결과가 같은 버그 수정
- **수집**
  - `V2_GAIA_RELEASE`를 바꾸면 모든 수집기 캐시가 지워지던 문제.
  - 시간 초과 기록에 `cache` 열이 빠진 문제.
  - PN 위치에 B1950 좌표를 J2000으로 쓸 수 있던 문제.
- **앱**
  - 북마크 페이지에서 패널과 버튼이 서로 다른 북마크를 가리키던 문제.
  - 닫기 직전에 쓴 노트가 사라지던 문제.
  - 로그 창이 줄을 놓치던 문제.
  - 읽기에 실패한 결과에서 다른 천체를 선택하던 문제.
  - 저장 실패(OSError) 처리.
- **벤치마크**
  - `build_desi_truth --exclude`가 표본을 뽑은 뒤에 적용되어 칸이 모자라던 문제.
  - `fit_fusion_weights --drop-keys` 비교 실험에서 뺀 키가 사전 가중치로 다시 들어가던 문제.
  - 보고서의 NaN 값.
- **검증 스크립트**: RA 0°/360° 경계를 넘는 대응을 놓치던 문제.
