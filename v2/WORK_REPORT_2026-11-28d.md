## 4. 과제 거

### 4.1 두 재생성 경로 (`build-reference-objects.yml`, `v2_desi_external_validation.yml`)

* **무엇이 문제였나**: 앞의 것은 작업 가지에서 빌더를 건드린 push마다 자동으로 `v2/reference_objects`를 재생성해 커밋했다. 뒤의 것은 수동이지만 첫 작업이 서버에서 목록을 다시 뽑고 마지막 작업이 `truth.csv`와 `catalog_features`를 커밋본 위에 덮어썼다. 검토 세션은 두 경로가 지금은 돌지 않는다고 확인했으므로 이번 일은 "안전장치 추가"다.
* **바꾼 것**: 두 워크플로 모두 기본 실행이 (a) 커밋된 파일의 SHA-256을 매니페스트와 대조하고 (b) 뒤의 것은 **커밋된 자료**를 평가해 결과 파일 두 개만 커밋한다. `regenerate=true`(명시 입력)일 때만 서비스를 다시 부르고, 결과는 `v2/reference_objects_regenerated/<run id>/`, `v2/benchmark/desi_external_regenerated/<run id>/` 옆 폴더에 쓴다. 커밋된 표를 바꾸는 일은 사람이 복사하고 `truth_manifest.py build`를 돌려 한 커밋에 넣는다. `build-reference-objects.yml`의 push 트리거는 지웠다. 빌더는 `V2_REFERENCE_OBJECTS_OUT` 환경 변수로 출력 폴더를 바꿀 수 있고(기본은 그대로, 시험이 고정), 이것이 "옆 폴더에 쓰기"의 수단이다.
* **버린 대안**: (i) 재생성 결과를 자동으로 덮어쓰되 매니페스트를 갱신하는 봇 — 봇이 "결정"을 대신하게 되어 이번 문제를 그대로 재현한다. (ii) 재생성 입력을 아예 없앰 — 재생성 능력이 필요한 때(서비스 변경, 다시 뽑기 결정)가 있다. (iii) `workflow_dispatch` 입력 없이 이름만으로 구분 — 실수로 덮어쓰기가 쉬워진다.
* **시험** `test_truth_manifest.py` 8개: 일치 / 레지스트리·매니페스트가 같은 표 · 파일 / 빌드의 결정성(시계 없음) / 바뀐 값·번호 재매김의 구분 / 짝 디렉터리 이름 비교 / **정답표를 `git add`하는 모든 워크플로가 `workflow_dispatch` 전용** / 두 경로의 기본 동작 / 빌더의 환경 변수 우회. 변이 확인 둘: 트리거에 `push`를 넣으면, 정답표 한 바이트를 바꾸면 각각 실패한다.
* **한계**: 실제 GitHub Actions 실행은 하지 않았다(규칙: 워크플로 실행 금지). 워크플로 로직은 YAML 구조를 읽는 시험으로만 확인했다.

### 4.2 SHA-256 매니페스트

`benchmark/truth_manifest.py`(`build` / `verify` / `show`)와 `truth_tables_manifest.json`: 14개 항목 = 과제 파의 조사 표 11행(1행은 `desi_external`·`desi_fusion` 둘, 6행은 mira·rr_ew 한 묶음) + 결정적 2개(`truth_data/ground_truth.csv`, `Classifier/star_truth.csv`; 헤드라인 SDSS 수치가 기대는 것). 파일마다 SHA-256, 바이트, 행 수, `benchmark_id` 집합의 해시(번호 재매김을 같은 행 수로도 잡는다)를 기록한다. 세 벤치마크의 `catalog_features`는 짝 디렉터리로 파일 단위 해시를 기록하되 시험과 워크플로는 **파일 이름 집합**만 비교한다(다른 워크플로가 같은 행의 열을 일부러 다시 모으므로: `augment-ls-columns`, `recollect-ps1-features`). `--paired strict`는 감사용이다. 시계·커밋 해시를 넣지 않아 같은 파일이면 같은 매니페스트가 나온다. 과제 자의 `Classifier/truth/fixed/truth_manifest.json`과 같은 취지(Sandve Rule 3: 쓰는 입력을 정확히 기록)이고, 구조는 그쪽(`sets` → 파일 해시 → 클래스별 id 해시)과 맞췄으나 위치와 이름은 따로 두었다(그쪽은 독립 정답 집합 동결용).

## 5. 과제 너: AllWISE `eeMaj`와 순서 키

### 5.1 무엇을 만들고 왜 그렇게 만들었나

`allwise`(2.62.4)는 `eeMaj`를 `poserr_arcsec`에 넣는다. 이 값을 두 곳이 읽는다: 연결 반경과 점수(`effective_sigma_arcsec`, PSF/6 하한 1.017″가 AllWISE 행의 대부분을 붙든다)와 1단계의 **처리 순서**(`_anchor_key`, 하한 없음). 그래서 분리 변형을 만들었다(모두 기본 꺼짐).

| 변형 | σ(반경·점수) | 순서 키 |
|---|---|---|
| `allwise` | eeMaj(하한 적용) | eeMaj |
| `allwise_order` (`V2_POSERR_NATIVE=allwise_order`) | base | eeMaj |
| `allwise_sigma` (`V2_POSERR_NATIVE=allwise_sigma`) | eeMaj | base |
| `floored` (`V2_ASSOC_ORDER_KEY=floored`) | base | **하한 적용 σ**(`effective_sigma_arcsec`, 이동 보정 없음): 모든 카탈로그(AllWISE 1.017″, GALEX 0.883″, 2MASS 0.42″) |

구현은 감지 행의 비공개 키 `_order_poserr`(없으면 기존 경로)와 `order_poserr_arcsec()`뿐이다. 설계 이유: (i) 순서 키만 따로 바꾸려면 σ와 키가 다른 값을 가질 수 있어야 하는데 `poserr_arcsec` 하나로는 불가능하다. (ii) 비공개 키(밑줄)라 CSV에 열이 늘지 않는다(꺼진 상태의 출력은 바이트 단위로 같다. 실제로 확인). (iii) `floored`는 순서 규칙의 문헌 근거가 없다는 점(`LITERATURE_ASSOCIATION_ORDER_2026-11-25.md`: 문헌은 경쟁 후보를 점수로 가르고 순서 규칙을 주지 않는다)을 코드 주석에 명시하고 "행을 연결 반경이 받는 만큼 정밀한 것으로 줄 세운다"는 일관성 논거만 적었다. 시험은 `test_order_key_switches.py` 7개(앵커가 누구인지를 가르는 합성 장면 포함; 변이 확인: `_anchor_key`가 새 키를 무시하면 그 시험만 실패).

### 5.5 판단과 제안

* `allwise`(eeMaj)를 채택할 근거가 약하다: 순이득 `right_object` +0.44 %, 놓침 −3.3 %, 우연 연결 +0.6 %p(저위도 +1.1–1.3 %p).

* `measure_association.py`의 `correct`와 이동 대조의 정의를 `right_object`·앵커 무관 정의와 **함께** 보고하도록 고치는 것을 제안한다(이번에는 도구를 고치지 않고 요약 도구에서 파생열로만 더했다).

## 6. 과제 더: 깊은 COSMOS 26개 영역의 문헌 행

`benchmark/deep_cosmos_literature/README.md`에 구성과 실행 순서. **이 세션은 수집을 하지 않았다**.

* **워크플로** `v2_deep_cosmos_literature.yml`: `workflow_dispatch` 전용, `validation-data`의 `deep_cosmos_lit/<run id>/<field>/`(블라인드 묶음 경로는 건드리지 않음), Gaia 가용 확인 없음, 요청마다 3–5초(`throttle`), 동시에 2개 영역, `push_with_retry.sh`, 영역마다 `run_info.json`. 먼저 **probe** 작업이 NED·SIMBAD의 표 목록을 읽어 필요한 열·단위가 다르면 실행을 멈춘다(SIMBAD `coo_err_maj`가 mas에서 다른 단위로 바뀌면 1000배 오차가 나므로 단위도 확인).
* **수집기** `collect_deep_cosmos_literature.py`: SIMBAD는 **기본 수집기를 그대로 부르고**(같은 열, 같은 질의) `coo_qual`과 `otypes`를 별도 요청 1개로 더한다. 따라서 **기본 수집 출력은 바뀌지 않는다**(시험이 `MAIN_COLUMNS`를 고정). 수집기를 바꾸고 스위치 뒤에 두는 대안은 버렸다: 어차피 별도 요청이 필요하고 기본 출력의 바이트 동일성 보증이 필요 없어진다. NED는 콘 검색 행 + `NEDTAP.objdir`의 불확실성 타원을 이름으로(안 맞으면 0.3″ 위치로) 붙인다. 콘 질의가 거부되면 이름 150개씩 묶어 묻는다.
* **오프라인 병합** `merge_deep_cosmos_literature.py`: 블라인드 `raw/<tag>/`의 **복사본**에 두 파일을 더한 새 디렉터리를 만든다. 블라인드 파일은 쓰지 않고(전후 SHA-256 비교), `--out`이 이미 있으면·블라인드 밑이면·이미 SIMBAD/NED 파일이 있는 묶음이면·수집이 끝나지 않은 영역이면 거부한다.
* **스위치** `V2_ANNOT_ASSOC=qual`(SIMBAD `coo_err_maj`를 등급 하한으로 받쳐 읽기, 오차가 없으면 등급의 값; 등급 A의 0.005″는 문서에 숫자 경계가 없어 **이 프로젝트의 가정**), `ned_unc`(타원 장반경 / 2.448; 95 % 가정은 미확인).
* **분석** `analyse_deep_cosmos_literature.py`: 문헌 전용 몫, 가장 가까운 탐사 객체까지의 거리 분포를 무작위 대조군과 비교, 변형별 새 연결과 다리, 열 채움 비율. **COSMOS 2′ 저장 자료에서 `typed_close`의 126행·55 / 0 / 71·0.6″ 밖 17행을 그대로 재현**해 검증했다. 거리 분포: 2′ 영역에서 1.13″ 이상 구간은 대조군과 같다(관측 / 대조군 0.92 / 0.97 / 1.01 / 1.05).
