- 버전 번호는 `MAJOR.MINOR.PATCH`로 쓴다.

## 2.5.0 — 코드 단순화 · 메모리 정리 (병합 대기)
분류 결과는 같다.
- SDSS·DESI 벤치마크 예측 파일과 세부 분류 평가 결과가 바이트 단위로 동일하다.
- 실제 영역 최종 결과도 셀 단위로 동일하다. 예외는 아래 "형 보존" 3개 열뿐이다.
- 측정에는 NGC 4522 원자료를 6×6으로 복제한 3,096개 천체 영역을 썼다.

| 변경 | 이유 | 측정 |
|---|---|---|
| `v2/common.py` 신설: `load_module`(경로로 한 번만 import), `num`/`row_num`/`text`, `records`, `read_table`/`write_table` | 같은 importlib 보일러플레이트가 23개 파일에, 같은 숫자·문자 변환 함수가 14개 파일에 복사돼 있었음. 한 곳에서 고치면 모두에 반영되게 함 | 실행 경로의 개별 로더 23 → 0개(연구용 하네스 제외), `_num`/`_text` 사본 14 → 5개(성격이 다른 앱 UI·SOS 수집기·외부은하 축 등) |
| `records()`: 행 dict에 **빈 칸을 넣지 않음** | 통합 표는 약 1,300열인데 83 %가 빈 칸. `to_dict("records")`가 3,096개 천체에 대해 약 400만 개의 파이썬 객체를 만들어 최대 메모리를 결정함. 행을 읽는 코드는 모두 `.get`을 쓰고 없는 키를 NaN과 같게 처리함(전수 확인) | 7단계 386 → 231 MB |
| 단계 사이를 **메모리로 전달**(`pipeline.py`). 각 단계 `run()`은 경로나 DataFrame을 받고, 출력 경로가 있을 때만 씀 | 단계마다 넓은 표 전체를 CSV로 쓰고 다시 읽었음(7회). 6단계는 검사만 하면서 같은 표를 통째로 복사하고 있었음. 명령줄 사용법(워크플로·검증 스크립트)은 그대로 유지 | 전체 20.2 → 8.6 s. 중간 CSV 7개(약 57 MB)는 `--keep-intermediate`일 때만 씀 |
| 형 보존(위 변경의 부수 효과) | CSV 왕복이 값을 바꾸고 있었음: 2MASS `Cflg` "000" → 0.0, SDSS `type` 6 → "6.0", 부동소수 마지막 자리 | 분류 결과는 동일. 해당 3개 열의 표기만 원래 값대로 바뀜 |
| `df.copy()` 후 열 추가 → `assign`/`concat` | 넓은 표 전체를 복사한 뒤 열 몇 개를 더하고 있었음. pandas 3의 copy-on-write에서는 `concat`이 기존 열을 복사하지 않음 | 4단계·7단계·세부 분류 단계의 복사 제거 |
| 색 kNN 거리 블록 1024 → 256행 | 1024 × 8,820 × 8 B = 72 MB 블록과 임시 배열 2~3개가 동시에 생김. 행끼리 독립이라 결과는 같음 | 해당 계산 137 → 82 MB, 0.50 → 0.12 s(캐시 효율) |
| 전체 코드 `black` 정리(줄 길이 120) | 한 줄에 여러 문장, 1칸 들여쓰기 등으로 읽기 어려웠음. black은 구문 트리가 바뀌지 않음을 검사한 뒤에만 고침 | 107개 파일 서식만 변경 |
| Tkinter 초안 앱(`finding_objects_app.py`)과 그 전용 `backend.py` 삭제 | Qt 앱이 모든 기능을 대신함. 둘 다 다른 곳에서 쓰이지 않음(git 이력에 남음) | 약 300줄 감소 |
| `v2/VERSION`, `CHANGELOG.md`, CLAUDE.md 규칙 7 | 사용자 요청: 보고서를 패치 버전별 변경 사항과 이유로 작성 | 앱 제목에 버전 표시 |

전체 결과(3,096개 천체): 실행 시간 20.2 → 8.6 s, 최대 메모리 407 → 312 MB, 출력 파일 8 → 3개.
작은 영역(88개 천체): 1.3 → 1.1 s, 101 → 93 MB.
