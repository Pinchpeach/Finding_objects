**교차 검증 결과로 되돌린 것**

2.18.0의 Gaia 분류 점수 하한(0.5)은 철회했다.
- 근거로 삼은 "0.5 미만 정답률 35 %"는 Cepheid·RR Lyrae·LPV·미라만 있는 정답 세트에서 잰 값이었다. 거기서는 다른 유형(식쌍성·자전)의 낮은 점수 판정이 정답이 될 수 없었다.
- 측정 가능한 유형에서는 이 하한이 맞은 판정 12개를 "변광"으로 바꿨다.
  - Cepheid 정확 일치: 93.2 → 90.4 %.
  - RR Lyrae: 82.4 → 81.6 %.
  - LPV: 63.6 → 62.4 %.
- 철회 후 교차 검증에서 2.15.0 값으로 돌아왔다.
  - Cepheid 93.2 %.
  - RR Lyrae 82.4 %.
  - LPV 63.6 %.
  - 미라 94.8 %(계열 99.6 %).
- 행성상성운(PN) 정확도는 92.8 → 89.2 %가 됐다.
  - 정답 세트는 Acker(1992) PN 목록이다.
  - 그중 10개를 HASH(2016)가 PN이 아닌 코드(모방체 등)로 분류해, 이제 PN으로 부르지 않는다.
  - 더 최근에 정리된 HASH 판정을 따른 결과라, 오류라기보다 두 카탈로그의 불일치다.
  - 판정한 것의 정밀도는 0.996 → 0.957이다.

## 2.19.0 — 전체 코드 검수: 개선과 메모리 누수 (#16)
세 영역(앱, 자료 수집, 전처리·분류기)을 나눠 검토하고, 지적 사항은 코드에서 실패 경로를 확인한 뒤 고쳤다.

**메모리 측정**: 한 프로세스에서 같은 파이프라인을 8번 연속 실행했다.
- 추적 메모리: 1.6 → 1.7 MB로 일정.
- 모듈 수: 603으로 일정.
- 결론: 파이썬 객체 누수는 없다. 최대 RSS가 실행당 약 1 MB 늘지만, 추적 메모리가 일정하므로 할당자 동작이다.
- 앱은 실행마다 별도 프로세스(QProcess)를 쓰고, 모델·지도·로그도 교체되거나 상한이 있다(5000줄).
