**결과가 바뀌는 변경은 하나도 켜지 않았다**(기본값 그대로, PATCH). 이유는 6절: 채택 기준 중 "set B·벤치마크 정확도"를 이 환경에서 잴 수 없었다.

## 1. 한 줄 결과

1. **연관 단계를 처음으로 정답(COSMOS2020)에 대어 쟀다**(26개 깊은 영역, 보정 15·시험 11개 영역은 지표를 보기 전에 이름 해시로 고정). 저해상도 목록의 **거짓 연관율**(정답 대비)은 AllWISE **2.09 %**(Wilson 1.8–2.4), 2MASS **0.10 %**, GALEX **6.2 %**이고, 연관 가능했던 행을 **놓친 비율**은 AllWISE 13.8 %, 2MASS 1.5 %, GALEX 22 %다.
2. **옮긴 목록 시험은 정답 대비 거짓율보다 훨씬 크게 나온다**: AllWISE 7.6 %(정답 2.1 %, 3.6배), 2MASS 3.7 %(0.1 %: 거짓이 1건뿐이라 배율은 의미 없음), GALEX 30 %(6.2 %, 4.9배). 두 시험은 다른 양을 잰다(옮긴 목록은 "짝이 없는 행이 우연히 붙을 확률", 정답은 "붙은 행이 틀릴 확률"). 2.49.0의 1.75σ·2.5σ 문턱은 정답 대비로는 **보수적**이다. 그러나 문턱을 풀어도 얻는 것이 작다: AllWISE 재현율은 문턱 없음에서도 68 %에 그친다.
3. **조각은 대부분 Legacy Surveys(LS) 한 행**(81 %)이고, 정답 천체의 7.6 %에 붙어 있다. 가장 큰 몫으로 보이는 원인: **두 Tractor 모형(예: PSF + REX, REX + EXP)이 한 천체를 둘로 나눌 때, 얕은 서베이 행을 가져간 쪽도 "큰 은하(host)" 조건을 만족해 기존 규칙의 후보에서 빠진다**(아래 변형 hc가 중복 행의 56–60 %를 없애는 것으로 확인). 이 경우를 후보로 허용하면(`V2_FRAG_HOST_CANDIDATE=1`) 같은 천체의 중복 행이 **56–60 % 줄고**, 조각 있는 정답 천체가 21–24 % 줄며, 틀린 병합은 +25/+13개(0.5 %p 안쪽), 라벨 변화 0이다.
4. **사후확률** `L/(L+1)`은 AllWISE에서 합이 실제 짝 수의 0.979배(ΣP = N★ 검사), GALEX에서 0.874배다. **Fleuren의 `R = L/(ΣL + 1 − Q0)`는 합은 맞추지만(0.998) Brier 점수가 나빠진다(AllWISE 0.0215 → 0.0269, 2MASS 0.0013 → 0.0033)**: 채택하지 않았다. 대신 **보정 영역에서 맞춘 단조 재보정**이 시험 영역에서 ECE를 AllWISE 3.9 → 0.3 %, GALEX 13.7 → 0.9 %로 낮췄다(구현은 하지 않음, 6절).

GALEX는 반대로 핵이 모형의 1.33배다. 하한 PSF/6이 꼬리를 뭉뚱그려 흡수한다는 문헌(Wilson & Naylor)과 같은 그림이다. **동시 배정**은 이 자료에서 이득이 거의 없다: 같은 목록의 다른 행에 막혀 놓친 행이 AllWISE 28개(전체 행의 0.24 %), 그중 막힌 행이 정답에 더 가까웠던 것 10개.

**정의**(수치를 보기 전에 `measure_association.py` 머리말에 적음)
- 정답 기준 집합 R = COSMOS2020 중 HSC i < 25. 해상도 높은 행(LS, PS1, SDSS, Gaia, SGA, Galaxy Zoo)은 0.6″ 안의 R의 가장 가까운 천체가 정답 id. 객체의 정답 id 집합 T(O) = 그 행들의 id(없으면 앵커 위치의 가장 가까운 R).
- 저해상도 행(AllWISE: IRAC ch1 플럭스, PSF 6.1″; 2MASS: Ks, 2.5″; GALEX: u 플럭스를 NUV 대용으로, 5.3″)의 **기대 짝**: 3 FWHM 안의 각 정답 천체 k에 `w_k = F_k·exp(−r²/2s²)`(s = FWHM/2.355)를 주고, `w`가 최대의 25 % 이상인 천체의 집합 A(d)(**너그러운**, 번짐 허용)와 최대 하나(**엄격한**)를 쓴다.
- **옳음**: 행이 붙은 객체의 T(O)가 A(d)와 겹침. **거짓**: T(O)를 알고 A(d)와 안 겹침. **놓침**: 붙지 않았는데 A(d)의 천체를 가진 다른 객체가 있음. 병합: 한 객체의 해상도 행이 1″(2″)보다 먼 두 정답 천체에 걸림. 조각: `score_independent_fields`의 `n_fragments`와 같은 규칙(HSC i < 23 정답 천체 둘레 1.5″ 안의 한 카탈로그 객체).
- **옮긴 목록 시험**(2.49.0 정의): 옮긴 복사본에서 옮겨진 행이 옮기지 않은 목록이 앵커인 객체에 붙은 비율. GALEX를 새로 더했다.
- 구간은 Wilson과 **영역 부트스트랩**(영역이 독립 단위)이다.

## 4. 조각 줄이기

### 4.1 왜 이런 구조인가 (분해)
LS만의 추가 객체 2,393개 중 같은 정답 천체의 것(r 등급이 있는 1,017개)을 보면 782개는 **추가 객체가 대응 객체(카탈로그 수가 가장 많은 쪽)보다 2등급 이상 밝다**. 예: LS 두 행(PSF 와 REX, 0.3–0.5″ 떨어짐)이 한 천체를 나누고, 위치 오차가 작은 PSF 행(앵커 순서 앞)이 PS1·AllWISE·SDSS 행을 가져갔다. 기존 `attach_galaxy_fragments`는 "큰 은하(host)" 조건(확장형 LS, 반광반경 > 0, GALAXY)을 만족하는 객체를 **후보에서 뺀다**. 두 객체가 모두 조건을 만족하면 어느 쪽도 묶이지 않는다. 나머지 정답 없는 추가 객체(1,257개)는 대부분 호스트보다 2등급 넘게 어두운 LS PSF 행인데, 호스트 중심에서 `max(r_e, 1″)`보다 멀어(660개) 묶이지 않는다.
- 밝은 별 마스크: LS 한 행 추가 객체 중 별 마스크 안(G < 16 별의 `1630″×1.396^−G`) 안에 있는 것은 **16개뿐**이다. 높은 은위도 6′ 영역에는 밝은 별이 드물다.
- 문헌 확인(원문, 2026-11-25): legacypipe `reference.py`의 `mask_radius_for_mag(mag) = 1630/3600·1.396^−mag`(도), `mask_mag = min(G, z+1)`, `isbright = mask_mag < 13`, `ismedium = mask_mag < 16`(440–457행), `get_reference_map`이 **BRIGHT 반경을 반으로 줄이고 MEDIUM은 전체 반경**을 쓴다(1051–1055행). 현재 코드(`halo_radius_arcsec`)는 G < 16 모든 별에 BRIGHT 몫(0.5R)을 쓴다. SGA는 `radius = d26/2`(′), `keep_radius = 2×radius`이다.

- **halo1**(MEDIUM 마스크 전체 반경): 헤일로 묶음이 942 → 1,714개로 늘고 틀림은 9 → 21. **이 영역으로는 판단할 수 없다**: COSMOS2020이 포화된 밝은 별 둘레를 가리므로 "정답 없음"이 아티팩트인지 정답에 없는 진짜 천체인지 가를 수 없다. 밝은 별이 많은 영역(set B)이 필요하다.
- 속도: 세 묶기 단계가 영역당 1.0–1.3초(9,053개 천체)이고 hc도 같다. 1단계에는 `likelihood_ratio` 두 열만 더했다(결과 동일).

### 4.3 채택하지 않은 이유
채택 기준(지시서 5번) 중 **"set B·벤치마크 정확도가 McNemar로 나쁘지 않을 것"**을 이 환경에서 잴 수 없었다(set B 원자료는 `validation-data`에 압축 제품만 있고 연관을 다시 돌릴 원자료가 없다). 그래서 모든 스위치의 **기본값을 2.41.0 그대로** 두었다. `experiment-ab-fields.yml`에 변형 `fraghc`, `fragm15hc`, `halo1`을 넣었으므로 `variants: base fraghc fragm15hc halo1`로 89개 영역 A/B를 돌리면 판단할 수 있다(정확도와 McNemar는 `compare_ab_fields.py`가 낸다. **조각 수는 아니다**: 그 수를 세는 `score_independent_fields.field_matches`는 부모 밑에 묶인 행까지 세므로, 묶기 스위치의 효과가 보이지 않는다. 병합 전 검토에서 확인했다. A/B 전에 최상위 객체만 세는 수를 더해야 한다).

## 5. 사후확률, 오차 모형, 동시 배정

### 5.1 사후확률 (문헌 원문 확인: Fleuren et al. 2012, arXiv:1202.3891v2)
- 식 (2) `P(id|r,m) = L/(L+1)`은 우리 현재 식(`density_l/(density_l+ρ)` = `LR/(LR+1)`)과 같다. 식 (3) `R_j = L_j / (Σ_i L_i + (1 − Q))`는 다른 후보를 반영한다. Q0 추정(식 8): `1 − Q0 = S̄/R̄`(원천 둘레의 빈 원 / 무작위 위치의 빈 원). 우리 `L`에는 등급 분포 q(m)이 없어(색 가중치만) 두 형태를 시험했다: `R`(그대로)와 `Q0·L`로 바꾼 `fleuren_q`(사전 오즈 Q0/(1−Q0)).
- 1단계에 `likelihood_ratio`, `lr_sum_candidates` 열을 더했다(결과 동일: 기존 열 전부 같음, `test_association_diagnostics.py`).
- **Q0**(빈 원 세기, r ≥ 2″의 중앙값, 영역별): AllWISE **0.984**(1−Q0는 r 1.5″ 0.12 → 6″ 0.00), 2MASS 1.00, GALEX **0.83**(1−Q0 0.49 → 0.07). GALEX는 반지름에 크게 의존해(0.07–0.49) 값이 불안정하다.
- **신뢰도 검사**(정답 짝이 있는 행 기준 = Q0 ≡ 1에 해당; 시험 영역; 점수 `current`가 현재, `fleuren`이 `R`):

| 목록 | 점수 | n | Brier | ECE | ΣP / 실제 짝 수 |
|---|---|---|---|---|---|
| AllWISE | 현재 | 3,250 | **0.0222** | 3.9 % | 0.981 |
| | Fleuren `R` | | 0.0288 | 3.9 % | 1.001 |
| | **단조 재보정**(보정 영역에서 맞춤) | | **0.0207** | **0.34 %** | 1.004 |
| 2MASS | 현재 | 408 | **0.00036** | 0.59 % | 0.994 |
| | Fleuren `R` | | 0.0032 | 0.67 % | 0.993 |
| GALEX | 현재 | 851 | 0.137 | 13.7 % | 0.868 |
| | Fleuren `R`(Q0 = 0.83) | | 0.107 | 10.7 % | 0.909 |
| | `R` with Q0 = 1 | | 0.062 | 5.7 % | 1.002 |
| | **단조 재보정** | | **0.058** | **0.91 %** | 1.003 |

  (26개 영역 전체: AllWISE ΣP/N★ 0.9785 → 0.9981(`R`), GALEX 0.874 → 0.914(`R`) / 0.996(Q0 = 1).)
- **읽기**: ① `R`은 합을 맞추지만 순위를 나쁘게 한다(AllWISE·2MASS Brier 악화): 사후확률이 이미 거의 1에 닿고(한 영역에서 AllWISE LR 평균 180) `ΣL`로 나누면 구분력이 줄어든다. ② 현재 사후확률은 **위쪽에서 단조가 아니다**: AllWISE에서 [0.999,1) 구간의 실제 옳은 비율이 91.5 %(281행), [0.95,0.99)는 99.9 %. ③ 보정 영역에서 맞춘 단조 재보정은 시험 영역에서 ECE를 크게 낮춘다. ④ 정답에 없는 짝(포화된 밝은 별 등)까지 거짓으로 세는 **무조건부** 검사는 COSMOS2020의 포화 별 가림 때문에 편향된다(2MASS 340행): `calibration_summary_unconditional.csv`에 두되 근거로 쓰지 않았다.
- **채택하지 않음**: `R`은 기준 미달(Brier). 단조 재보정은 효과가 크지만 ① 한 개의 높은 은위도 영역에서 맞춘 표라 밀도 높은 영역으로 옮겨지는지 모르고 ② `association_confidence`가 증거 가중에 쓰여 **라벨이 바뀌므로** 세트 C 채점이 필요하다. 라벨 변화는 구현하지 않았으므로 재지 않았다. **다음 단계 후보**: 목록별 재보정 표(`phot_prior.csv`와 같은 방식)를 set B로 검증.

### 5.2 오차 모형 (측정 + 설계, 구현 없음)
고립된(기대 짝이 하나) 행의 정답 천체까지 거리(`error_model.csv`):

| 목록 | 종류 | 행 | 현재 σ (중앙값) | 거리 중앙값 | 핵 σ(중앙값/1.177) | 핵/현재 | p99 | 핵의 3σ 밖 | 현재 σ의 2.5배 밖 |
|---|---|---|---|---|---|---|---|---|---|
| AllWISE | 고립 | 9,643 | 1.02″ | 0.45″ | **0.38″** | **0.37** | 8.1″ | 13.7 % | 2.8 % |
| AllWISE | 번짐 | 1,946 | 1.02″ | 1.46″ | 1.24″ | 1.22 | 9.8″ | 5.8 % | 16.6 % |
| 2MASS | 고립 | 1,070 | 0.43″ | 0.25″ | **0.21″** | **0.50** | 2.1″ | 9.7 % | 2.8 % |
| GALEX | 고립 | 2,330 | 0.89″ | 1.39″ | **1.18″** | **1.33** | 11.0″ | 9.0 % | 26.8 % |
| GALEX | 번짐 | 668 | 0.89″ | 2.84″ | 2.41″ | 2.71 | 11.4″ | 3.3 % | 63.5 % |

- 모형 σ = `max(poserr, PSF/6)`에 정답 위치 오차 0.1″를 더한 것. 레일리 분포라면 3σ 밖이 1.1 %여야 하는데 핵의 3σ 밖이 9–14 %다 = **가우스 핵 + 두꺼운 꼬리**(Wilson & Naylor 2017/2018a: 핵은 0.1″ 근처까지만 가우스, 밖은 오염원에 끌린 비가우스 꼬리). 현재 PSF/6 하한은 AllWISE·2MASS 핵보다 2–3배 넓어 꼬리를 흡수하고, GALEX는 핵보다도 좁다.
- **설계**(구현하지 않음): 우도 `f(r) = (1−w)·N(r; σ_핵) + w·N(r; σ_꼬리)`. σ_핵은 문서화된 위치 오차(AllWISE 86–157 mas, 2MASS 70–80 mas, GALEX 0.5″)와 앵커 오차, σ_꼬리 ≈ κ·FWHM, 꼬리 비율 `w`는 오염 지표 `Q = ρ·FWHM²`의 함수(AllWISE는 Q ≈ 0.06). 바꾸면 1.75σ·2.5σ 문턱을 보정 영역으로 다시 맞추고(2.49.0 방식, 옮긴 목록이 아니라 정답 거짓율을 쓰는 쪽을 권한다), 시험 영역으로 확인해야 한다. 표기 오차만 줄이고 꼬리를 두지 않으면 짝의 절반을 잃는다는 문헌 경고는 이번 측정에서도 맞다(핵만으로는 AllWISE 고립 행의 13.7 %가 3σ 밖).
- 한계: GALEX의 정답 대용(u 플럭스)은 NUV와 다른 천체를 고를 수 있어 거리가 부풀 수 있다.

### 5.3 동시 배정 (측정 + 설계, 구현 없음)
- AllWISE 놓침 1,594행의 내역: **후보 없음 1,174(74 %)**, 모호해서 안 붙음 392(25 %), **같은 목록의 다른 행에 막힘 28(1.8 %)**. 막힌 28개 중 막힌 행이 정답 천체에 더 가까웠던 것은 **10개**(전체 행의 0.09 %). 2MASS 2·1개, GALEX 6·4개.
- 후보 없음 1,174개의 75 %는 번짐(두 천체 이상이 25 % 넘게 기여)이고, 정답 천체 중앙값 거리가 2.0″로 옳게 붙은 행의 0.39″보다 훨씬 멀다: 번짐 행의 중심이 두 천체 사이에 있어 1.75σ 안에 앵커가 없다.
- **판단**: 일대일 강제(Budavári & Basu 2016의 헝가리안, 섬 단위 `linear_sum_assignment` + Marrese 식 다대일 예외)는 이 영역에서 얻을 것이 거의 없다(막힘 0.24 %). 놓침의 큰 몫은 번짐 행의 오차 모형 문제(5.2)다. 은하면처럼 밀도가 높은 영역에서는 달라질 수 있으나(문헌의 모의는 400개/arcmin²) 측정하지 않았다.

## 7. 한계 (지시서 6번)
- **COSMOS는 높은 은위도의 한 영역이다**(6′ × 26 = 약 2.9 deg², 한 하늘 구역). 은하면의 혼잡(밀도 100배)과 밝은 별 헤일로, 근거리 이중성은 대표하지 않는다. 동시 배정과 오차 모형의 꼬리 크기는 밀도에 의존하므로 이 숫자를 은하면에 옮기면 안 된다.

## 9. 설계 이유 (규칙 6)
- **정답을 먼저**(문헌 1.6절의 순서): 정답 없이 뒤의 변경을 하면 2.48.0 A/B처럼 "고침 0, 깨짐 0"이 된다. 그래서 변경 전에 정의를 코드 머리말에 고정하고 영역을 보정/시험으로 나눴다.
- **정적 문턱 곡선**: 문턱마다 파이프라인을 다시 돌리면 26 영역 × 10여 번이다. 문턱 없는 한 번의 실행에서 `normalized_separation > k`를 안 붙은 것으로 보는 근사를 쓰고, 현재 문턱에서 실제 실행과 맞는지 확인했다(AllWISE 7,841 대 7,929).
- **조각은 "재생" 방식**: 묶기는 분류 뒤에 라벨을 바꾸지 않으므로 저장된 `classified_objects.csv`에서 세 단계의 역할만 지우고 다시 적용하면 된다. 변형 하나가 2분이다(전체 파이프라인은 영역당 2–3분). 재생이 기준과 100 % 같은 것을 먼저 확인했다.
- **스위치는 환경 변수, 기본은 옛 값**: A/B 워크플로가 같은 방식으로 변형을 만들기 때문에 set B에서 같은 이름으로 돌릴 수 있다. 코드 경로는 기본에서 바뀌지 않는다(시험).
- **`R`을 1단계에 넣지 않고 열만 추가**: 채택 전에 결과를 바꾸지 않으려고 `likelihood_ratio`와 `lr_sum_candidates`를 기록만 하고 계산은 측정 쪽에서 했다. Q0를 바꿔도 다시 돌릴 필요가 없다.
- **버린 것**: 문턱만 푸는 재보정(재현율 +4점에 거짓 2배), `R`(구분력 악화), 일대일 배정 구현(막힘 0.24 %), 밝은 별 마스크 전체 반경(이 정답으로 검증 불가).
