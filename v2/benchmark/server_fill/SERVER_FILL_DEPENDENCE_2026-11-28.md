# 서버가 앞에서부터 채운 표본에 벤치마크 수치가 얼마나 기대는가 (2026-11-28, 측정과 제안만)

**이 문서가 하는 일**: 과제 파의 조사는 일부 정답표가 "서비스가 `ORDER BY` 없이 앞쪽 행부터 채운 것"처럼 생겼다는 흔적(RA가 창의 아래쪽 가장자리에 몰림)을 찾았다. 여기서는 그 표본에 기대는 수치가 무엇이고, 얼마나 기대는지를 잰다. **문서의 수치·표·코드는 바꾸지 않았다**(제안만). 예측은 `PREDICTIONS_2026-11-28.md`(커밋 3c1f007)에 먼저 적었고, 도구는 `server_fill_dependence.py`, 결과는 `results_2026-11-28/`.

## 4. DR16Q 300행과 검증 계획

* 커밋된 `QSO_SPECTROSCOPIC` 300행: RA **1.60–3.26°**, Dec −11.2–36.1°(원격 목록의 앞 6,000행).
* 검증 계획 `validation/plan.csv`(2.46.2)의 같은 유형 10개: RA **0.14–1.51°**. **10개 모두 커밋된 표에 없다.** S6의 RA 범위 예측(0–4°)은 맞았으나, 계획이 표 밖이라는 것은 예상하지 못했다.
* 계획 520개 중 **54개(10.4 %)**가 커밋된 표에 없다. 10개 중 0개 있는 유형이 4개(`QSO_SPECTROSCOPIC`, `DELTA_SCUTI_HADS`, `ECLIPSING_BETA_LYR`, `ROTATIONAL_VARIABLE`), `DELTA_SCUTI` 2/10, `CEPHEID_CLASSICAL` 6/10, `YSO_VARIABLE` 8/10(`reference_plan_overlap.csv`).
* 커밋 이력상 표는 2.46.1(85f8853), 계획은 2.46.2(a6d47e1)에서 한 번씩만 커밋되었다. 그런데도 계획의 객체가 표에 없으므로 **계획은 지금의 표와 다른 빌드에서 뽑혔다**. 원인은 확인하지 못했다(그 빌드가 어느 실행이었는지 저장소에 기록이 없다). 이것이 "다시 돌리면 다른 표본이 나온다"는 우려의 직접 사례다.
* 영향: `REFERENCE_VALIDATION_2026-11-07.md`의 유형별 결과(`QSO_SPECTROSCOPIC` 8/10 등)는 지금 커밋된 표에 없는 객체들의 값이다. 결과 자체가 틀린 것은 아니지만 "커밋된 참조 표를 검증했다"고는 말할 수 없다.

## 5. 제안 (실행은 사용자 결정)

1. **문서 행에 표본의 성격을 적는다**: README `:143`의 DESI 칸과 `ALGORITHM.md:166`에 "RA 10° 창 8개의 아래쪽 가장자리 조각"이라는 설명과 셀 단위 95 % 구간(88.9–94.0 %)을 병기. 개요 PDF·발표 문구는 README와 같은 표현으로.
2. **README의 "플레이트 142개"를 확인한다**: 이 파일은 84개(`sdss_footprint.csv`). 두 목록의 합을 뜻한 것이면 그렇게 적는다.
3. **참조 표의 검증 계획을 표에 맞춘다**: `plan.csv`를 커밋된 표에서 시드 고정으로 다시 뽑거나, 계획이 다른 빌드에서 왔다고 `REFERENCE_VALIDATION_2026-11-07.md`에 적는다. 이 표는 이제 SHA-256 매니페스트의 보호를 받는다(`truth_tables_manifest.json`).
4. **`desi_external`을 다시 뽑게 된다면**(별도 결정): 질의에 안정적 무작위 키(`TargetID` 해시 등)로 `ORDER BY`를 두어 창 전체에서 뽑고, 옛 표는 `desi_external_v1`로 남긴다. 분할 키 설계(`../split_key/SPLIT_KEY_DESIGN_2026-11-28.md`)의 B안(분할 고정)이 그때 새 객체에만 적용된다. 이 환경에서는 서비스에 접속할 수 없으므로 GitHub Actions에서 해야 한다(그리고 이 변경은 이전 수치와 비교 가능성을 끊으므로 CHANGELOG에 기록할 일이다).

## 6. 한계

* `desi_external`의 표본이 하늘의 대표가 아닐 때 정확도가 **어느 방향으로 얼마나** 틀리는지는 모른다. 잰 것은 불확실성의 크기(셀 단위 구간)와 창 사이 차이뿐이다.
* 규칙 기준선이지 README의 융합 수치가 아니다. 융합 가중치는 이 표본의 train 분할로 적합되었으므로, 적합이 표본의 하늘 조각에 맞춰졌을 가능성은 이 측정으로는 다루지 않았다.
* 22 %의 넓은 셀의 원인(희귀 셀에서 서버 앞 4배 행이 넓은 RA에 걸침)은 가설이다.
