## 3. 설계 이유
- **검토를 영역별 병렬로, 수정은 직접**: 각 검토자는 저장소를 고치지 않고 재현 스크립트와 함께 보고만 하게 했습니다. 보고를 하나씩 확인한 뒤 고쳐, 확인되지 않은 "개선"이 섞이지 않게 했습니다.
- **SDSS 큰 반경**: astroquery의 원뿔 모드는 서버 교차 ID 기능이라 3′ 제한이 있습니다. SkyServer SQL 함수(`fGetNearbyObjEq`)를 직접 쓰는 대안은 컨테이너에서 시험할 수 없어, astroquery가 지원하는 사각형 모드(제한 없음)에 RA 폭 1/cos δ 보정과 원 자르기를 더했습니다. 3′ 이하는 이전과 같은 경로입니다.
- **Gaia 동기 질의**: 2000행 상한은 서버 쪽 동기 작업의 한계라 늘릴 수 없습니다. 꽉 찬 결과를 실패로 보면 이미 있는 VizieR 대체 경로(전체 원뿔)가 쓰입니다.
- **부분 실패는 캐시하지 않음**: 이미 있는 `*_query_status` 규칙(LAMOST·SDSS 선)을 그대로 따랐습니다. 새 규칙을 만들지 않아 캐시 코드는 바뀌지 않습니다.
- **ID를 문자열로**: pandas의 `"string"` 형은 결측을 `<NA>`로 바꿔 규칙의 "nan" 검사와 어긋나므로, 결측이 NaN으로 남는 `str`(object)로 읽습니다. 한 함수(`Preprocess/table_io.py`)로 모든 단계가 같은 규칙을 씁니다.
- **SFD 적색화 거리 보정**: SFD는 시선 전체의 먼지라 가까운 별에는 과합니다. 3차원 먼지 지도(Green+2019 등)를 수집하는 대신 지수 먼지 원반(Drimmel & Spergel 2001, 척도 높이 134 pc)으로 앞쪽 몫을 계산했습니다. 추가 질의가 없어 속도 영향이 없고, 시차가 없으면 이전과 같습니다. 세부 분류 벤치마크에서 지표 1개만 소폭 개선되었습니다(벤치마크 별은 대부분 GSP-Phot 소광이 있어 이 경로를 거의 타지 않음).
- **SIMBAD MK 계급 우선**: 모듈 원칙("분광 라벨이 측광 기준보다 우선")에 맞추고, 물리 축과 세부 분류가 같은 근거를 쓰도록 했습니다.
- **북마크 = 스냅숏 + 경로**: 결과 폴더를 지워도 북마크가 의미를 잃지 않도록 이름·위치·분류를 함께 저장합니다. 같은 천체 판단은 이름, 없으면 1″ 위치(Gaia급 위치 일치보다 넉넉하고 다른 천체 간 거리보다 작음). 저장은 임시 파일 교체로 원자적이고, 손상 파일은 보존 후 빈 목록으로 시작해 앱이 멈추지 않습니다. 저장소는 Qt 없이 시험할 수 있게 분리했습니다. 별도 창이 아니라 같은 창의 탭으로 둔 것은 "열기"·"여기서 검색"이 메인 화면 상태를 바로 바꾸기 때문입니다.
- **코드 모양을 도구로**: 손으로 바꾸면 147개 파일에서 동작 차이를 만들기 쉽습니다. `black`은 구문 트리가 같은지 스스로 확인하고, 그래도 결과 파일을 바이트 단위로 비교해 동작이 같음을 확인했습니다. 설정을 `pyproject.toml`에 두어 앞으로 같은 모양을 유지할 수 있습니다.
- **릴리스 압축**: `upload-artifact`가 파일 권한을 버리므로 빌드 단계에서 먼저 압축합니다(Linux·macOS `zip -ry`, Windows `7z`). 압축 안에 최상위 `FindingObjects/` 폴더가 생깁니다.

## 4. 고치지 않은 것과 이유
- 4LAC·WISE 블레이자 띠, 격변 변광성: 2.22.0 보고서의 "남은 일" 그대로.
- PS1 MAST API 페이지 크기로 큰 원뿔이 잘릴 가능성: 네트워크 없이 확인할 수 없어 보고만 받음.
- 빌드된 앱 안에서의 실제 아카이브 수집: CI 스모크 시험은 오프라인 경로만 확인. 컨테이너에서도 시험 불가.
