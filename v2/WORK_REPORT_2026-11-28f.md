## 2. 과제 러

### 2.1 무엇을 만들고 왜 그렇게 만들었나

* **`measure_association.py`: 열 추가만.** `right_object`·`wrong_object`·`unidentified`(main의 `alone_*`로 계산), `shared`·`displaced`(객체 구성만으로 정해지는 조각 / 엉뚱한 객체 읽기), `shifted_any_pct`(이동한 행 중 객체에 이동하지 않은 카탈로그의 행이 하나라도 있는 비율)를 끝에 붙였다. 옛 열의 순서와 값은 그대로다(요약 도구의 앞 열이 같음을 비교로 확인). 이유: 2.60.9~2.62.6의 모든 결과 표가 옛 열 위치를 읽는다.
* **`shared`·`displaced`를 왜 더했나**: 최종 `right_object`는 "행의 객체가 정답 짝을 가졌는가"만 말하고 **조각을 못 본다**(단독 AllWISE 객체도 이미 정답을 가진 객체로 읽히므로 광학 객체와 합쳐도 `right_object`가 안 변한다). `same,nearest`와 2.61.0 순서 변경의 이득이 바로 그 조각 줄이기이므로, 이 둘을 앵커 무관 읽기로 따로 셌다(합성 시험 `test_shared_displaced_metric.py`).

* **표는 손으로 옮기지 않고 `right_object_tables.py`가 만든다**(28b·28c에서 보고서 숫자가 어긋난 일이 반복됨).
* **규칙을 시험으로 지킴**: `right_object_recount.HEADLINE`(결론에 쓰는 읽기)의 각 항목이 `METRICS.md` 표에서 "앵커 의존: 아니오 / 변형 비교: 예"로 적혀 있고 `correct`·`missed`·`rightly_alone`·`shifted_false_pct`는 "비교에 쓰지 않음"으로 적혀 있는지 시험이 문서를 읽어 확인한다.

첫 판의 예측(A–D, 옛 정의)은 폐기된 정의의 값이라 다시 판정하지 않는다(b0ec093의 README에 판정이 있다). 고친 정의에 대한 추가 예측(E1–E5, 새 요약을 열기 전에 커밋 b06fdf0, 옛 숫자를 이미 본 뒤라 맹검은 아님)은 **다섯 개 모두 틀렸다**: E1 `same_nearest` 확인 17 `right_object` +46 / +31 예측 → 0 / +17; E2 `file` −52 예측 → −31; E3 `floored` +135 ~ +160 예측 → **−179**; E4 `floored` 재라벨 몫 ≤ 94 % 예측 → 108 %; E5 순위 floored > … 예측 → floored가 꼴찌. 같은 방향으로 틀렸다: 새 정의가 옛 정의를 수십 행 보정할 뿐이라고 보았으나 단독 AllWISE 객체가 이미 "정답 객체"로 읽힌다는 사실이 `correct` 이득 대부분을 재라벨로 바꾸었다.

## 6. 오류와 고친 것

* **내 첫 `right_object`(`correct + rightly_alone`)가 앵커에 따라 움직였다.** 검토 세션이 찾았고 main이 `correct + alone_identified`로 고쳤다. 나는 이 지적이 main에 들어온 것을 보고서를 거의 다 쓴 뒤에야 알았고(병합 알림을 늦게 읽음), 고친 정의로 다시 재서 보고서 1–2절과 결과 폴더·`METRICS.md`를 모두 새로 썼다. 첫 판의 `same,nearest` "+46은 재라벨 0 %", `floored` "+129", 순서 변경 "+52", `eeMaj` "+0.44"는 폐기한다.
* 같은 정의의 허점: 최종 `right_object`도 조각을 못 본다. 그래서 `shared`·`displaced`를 더했고 `same,nearest`의 AllWISE 이득이 조각 합침임을 보였다.
* `run_right_object_variants.sh`가 빈 `V2_ASSOC_TIE_ORDER=`를 기본 변형에 넘겨 1단계가 `ValueError`로 멈췄다. 환경에서 `unset`하도록 고쳤다.
* 요약 도구(`summarize_native_error_variants.py`)에 `shifted_any_pct`와 `rightly_alone`의 변화량 열을 더했다(main의 최종판을 받은 뒤 같은 변경을 다시 얹음; 옛 결과 폴더에는 열이 없어도 돌도록 조건부).
* `doc_claims_check.py`의 `hc17`이 풀링 행(`all`)까지 더해 48,338개로 셌다 → 풀링 행을 빼고 24,169개로, 84 % 하한은 풀링 행의 값을 쓰도록 고쳤다.

## 8. 결정이 필요한 것 (검토 세션)

1. **참조 천체 목록(`reference_objects.csv.gz`)**: 계획 520개 중 54개가 목록에 없다. 선택지: (가) 2.46.1의 목록으로 되돌리고 SHA-256으로 고정(검증·문서 모두 520/520; 거 과제의 매니페스트가 이미 이 파일을 지킨다), (나) 현재 목록 유지 + 계획의 54개를 `plan.csv`에서만 "목록에 없음"으로 표시. 데이터 취급이라 내가 고르지 않았다.
2. **`floored`와 출력 위치 설계**: 28d §5.5의 보류 이유가 바뀐다. 첫 판은 "연관이 더 낫다(+129)"였으나 앵커 무관 읽기로는 AllWISE `right_object` −179, `displaced` +173이다. 위치 잔차(0.5″ 밖 4.51 → 3.27 %)와 우연 연결률(−2.07 %p)은 좋아진다. 위치만 좋게 하려면 순서 키를 바꾸지 말고 과제 버(출력 위치만 `best` 구성원)가 맞는 길이다.
3. **2.61.8의 `same,nearest` 설명**: "정답 연결 +46 / +32"는 AllWISE에서는 조각 합침, GALEX에서는 반이 진짜 `right_object` 이득이다. 채택 판단 문서의 표현을 "조각 줄이기(AllWISE) 및 `right_object` +1.07 %p(GALEX)"로 바꾸는 것을 제안한다(CHANGELOG 2.61.8·2.62.7 행은 병합된 행이라 새 행으로 정정한다).
4. **병합된 CHANGELOG 2.62.7 행의 `floored`: "+129 / −147 / −2.07 %p로 더 낫지만"**은 위 2번에 따라 정정이 필요하다(새 행에서 정정).
5. 문서: `NEXT_RELEASE_DOCS.md` 11–14·16번은 다음 릴리스에서 고친다. 세트 C 60개 영역 중 정답 있는 영역이 59개라는 점(15번)은 영역 하나가 정답 0개인 이유를 확인하지 못했다.
6. **"2.60.9 기준선 13.25 / 20.55 / 1.48 %"**는 현재 기본값의 값이다.
