# 작업 보고서 2026-11-25b — 작은 고정 목록을 첫 사용 때 한 번 받아 사용자 캐시에 두기 (2.60.7)

지시서(2026-11-25) 과제 2. 2.60.2 보고서 11.1절의 (가′)를 구현했다. 재배포가 아니라 **사용자 컴퓨터가 VizieR에서 한 번 받는 것**이다.
**기본값은 꺼짐**이다. 두 목록 모두 이용 조건을 원문에서 확인하지 못했고, 지시서가 "조건이 불분명하면 그 목록은 뺀다"고 했기 때문이다(5절).

## 1. 한 줄 결과

- 두 목록(Suh 2021 AGB 18,381행, Roma-BZCAT 5판 3,561행)을 `V2_LOCAL_LISTS=all`로 켜면 **첫 검색에서만 요청 1번씩(6–12초), 그다음 검색부터 두 수집기의 요청은 0번**이다. 켜지 않은 쪽(원격)은 영역마다 요청 4번(21–26초 스레드 시간).
- 답은 VizieR와 **같다**: 표·열·형·행 순서·모든 칸이 같고, `_r`(VizieR가 알려 주는 거리)만 최대 5×10⁻⁴′ 다르다(코드는 `_r`을 읽지 않는다). 비교 결과는 `benchmark/local_lists/local_vs_vizier_2026-11-25.csv`(7절).
- 수집 **벽시계 시간은 이 날 줄지 않았다**(건강한 날 임계 경로는 `desi_legacy`·`gaia_dr3`). 줄어든 것은 요청 수(영역당 −4…−8)와 두 수집기의 스레드 시간(영역당 21–26초 → 0)이다. 2026-11-23/24처럼 VizieR 미러가 죽은 날은 AGB 한 수집기가 요청 8–13번·84–110초였으므로 이득이 더 크다(2.60.2 보고서).
- 이용 조건 때문에 **사용자의 결정이 필요하다**(9절).

## 3. 무엇을 만들었나

`Get_data/local_lists.py`(새 파일), 수집기 두 곳(`agb_suh2021.py`, `bzcat.py`)이 `local_lists.cone(...)`를 먼저 묻는다. 앱 진행 줄(`app/progress.py`)은 `[lists] ...` 줄을 그대로 보여 준다(진행률은 올리지 않음).

- **첫 사용**: 전천 한 개 원뿔(반지름 10800′)로 표 전체를 VizieR에서 한 번에 받는다(`_catalog_utils.vizier_query`, 미러 failover·3–5초 대기 그대로). 행 수가 고정판과 다르면 **저장하지 않는다**. 표별로 `pickle.gz`(병합 전 검토에서 gzip ECSV로 바꿈, 10절)와 `manifest.json`(VizieR 표 ID·받은 날짜·행 수·SHA-256·크기)을 `$V2_CACHE_DIR/lists/<목록>/`에 쓴다. 진행은 `[lists] first use: downloading ... / downloaded N rows in S s`로 로그에 남는다.
- **이후 원뿔**: 사본에서 VizieR와 같은 모양(`TableList`, 행 없는 표 제외, `_r` 첫 열)으로 답한다. 수집기 코드는 원격과 로컬을 가르지 않는다.
- **갱신**: 받은 지 `max_age_days`(365일)가 넘었거나, 파일 해시가 manifest와 다르면 다시 받는다. 사용자가 `python v2/Get_data/local_lists.py refresh [목록]`(`status`, `remove`도 있다)으로 부를 수도 있다.
- **실패 시**: 다운로드가 실패하거나 사본 조회가 예외를 내면 **그 검색은 VizieR 원격으로** 간다(수집기는 실패하지 않는다). 실패한 목록은 600초 동안 다시 받으려 하지 않는다(병합 전 검토부터는 프로세스 사이에서도, 10절).
- **`V2_CACHE=0`**: 사본을 읽지도 받지도 않는다. "디스크 상태 없음"이라는 이 스위치의 뜻(차가운 측정)을 지키려는 선택이다.
- **`V2_LOCAL_LISTS`**: `auto`(기본) = 이용 조건을 원문에서 확인한 목록만 쓴다(지금은 없음) / `all` = 모두 / `0` = 쓰지 않음.
- 저장소와 앱 묶음에는 **목록 데이터가 없다**(`THIRD_PARTY_NOTICES.md`에 문구 추가).

## 4. 왜 이렇게 짰나 (대안과 버린 이유)

- **저장소에 사본을 두지 않았다.** 재배포 허락 문구를 못 찾았다(2.60.2). 사용자 컴퓨터가 직접 받는 것은 astroquery 디스크 캐시와 같은 종류의 일이다. 다만 "사용자가 받는 사본도 재사용이냐"는 법적 판단이라 기본 꺼짐으로 두었다.
- **전천 원뿔 한 번**: `Vizier.get_catalogs`는 쓰지 않았다. CDS 서버가 404를 줄 때가 있고 우리의 미러 failover는 `query_region` 경로에만 있다. 같은 경로를 쓰면 미러 기억·행 수 상한·대기 규칙이 그대로 적용된다. (VizieR의 `_r`까지 받기 때문에 한 요청에 모든 행이 온다.)
- **pickle.gz**: ECSV는 문자열 열의 가림(mask)을 잃고 CSV는 형을 잃는다(단위 시험에서 실제로 틀렸다). pickle은 astropy 표의 형·가림·단위를 그대로 보존한다. pickle은 신뢰할 수 없는 파일에는 위험하므로 **읽기 전에 SHA-256을 manifest와 대조**하고, 파일은 사용자 자신의 캐시 폴더에만 있다.
- **VizieR와 같은 모양으로 답하기**: 수집기·열 순서·이후 단계를 건드리지 않으려면 `TableList`와 같아야 한다. 같은지는 7절에서 실제 VizieR 원뿔과 비교했다.
- **`_r`**: VizieR는 표의 5자리 위치가 아니라 더 정밀한 내부 위치로 거리를 잰다. 우리는 표의 위치로 재서 최대 5×10⁻⁴′ 다르다. `_r`을 읽는 코드는 없으므로 같게 만들지 않았다.
- **BZCAT 위치는 시분각 문자열**(`12 24 54.46`/`+21 22 46.4`)이다. 처음 구현은 도 열을 가정해 ON 측정에서 `[bzcat] error`를 냈다. 측정이 잡은 오류다. `positions()`가 문자열을 배정밀도로 읽고(VizieR가 `_r`을 재는 위치), `cone()`은 예외가 나면 원격으로 간다(수집기가 로컬 실패로 죽지 않게).
- **두 목록만**: 지시서는 "표로 확인된 것"만 하라고 했다. 이용 조건과 판 고정이 확인되지 않은 것(2절)은 뺐다.

## 5. 이용 조건

원문 확인 여부를 `ListSpec.terms`에 적었다. 두 목록 모두 `terms_verified=False`다.
- Suh 2021: DOI 권리 표기는 "CDS 이용 규정을 보라"일 뿐이고 CDS 규정 페이지는 읽지 못했다. AAS의 2021-10-11 이전 논문 재사용 조항은 직접 읽었다.
- BZCAT: 인용 요청 문장만 있다(직접 읽지 못한 2차 확인).
- → `V2_LOCAL_LISTS=auto`(기본)에서는 **두 목록 모두 쓰지 않는다.** 결과와 속도는 2.60.6과 같다.

## 8. 실패와 대체 동작 시험 (`Preprocess/tests/test_local_lists.py`, 16개)

- 모양: VizieR와 같은 행·순서·`_r` 첫 열, 빈 표 제외, 반지름 경계 포함, 가려진 위치는 맞지 않음.
- 게이트: `auto`/`all`/`0`, 실제 두 목록은 이용 조건 확인 전까지 `auto`에서 꺼짐.
- 첫 사용: 한 번 받고 manifest를 쓰고 이후 요청 0번. 받기 실패 → 원격으로 대체, 600초 동안 다시 시도하지 않음. 행 수가 다르면 저장하지 않음. 손상된 파일 → 다시 받음. 오래된 사본·사용자 요청 → 다시 받음.
- `V2_CACHE=0`: 사본도 다운로드도 없음. 수집기가 로컬 답이 있으면 쓰고 없으면 VizieR로 감. BZCAT 수집기가 사본을 읽음. 앱 진행 줄이 다운로드를 보여 주고 수집기로 세지 않음. 시분각 위치를 배정밀도로 읽음. 조회가 예외를 내도 원격으로 대체(수집기가 실패하지 않음).

## 9. 사용자에게 필요한 결정

1. **켤지 말지**: CDS 이용 규정 본문(`licences_vizier`)을 읽을 수 있게 되면(또는 저자·AAS의 허락) `terms_verified=True`로 올린다. 올리기 전에도 사용자가 `V2_LOCAL_LISTS=all`로 켤 수는 있다.
2. **앱에 노출할지**: 앱 설정에 "작은 목록을 이 컴퓨터에 저장(약 1.3 MB)" 체크 상자를 둘지.
3. 켜기로 하면 **어떤 이득을 기대할지**: 건강한 날의 벽시계 시간이 아니라 요청 수(영역당 4번)와 미러 장애 날의 시간이다.

## 10. 한계

- 이득은 건강한 날 요청 수 −4…−8번뿐이고 벽시계 시간은 변하지 않았다(6절).
- 두 목록만 다룬다. 이용 조건을 확인할 수 있는 목록이 늘면 `SPECS`에 항목을 추가하면 된다(행 수·열 이름을 확인해야 한다).
- 판이 바뀐 사본(VizieR 표가 갱신됨)은 행 수 검사에서 걸린다. 이때는 저장하지 않고 원격을 쓰며 로그에 남긴다.


## 11. 병합 전 검토 (코드 개발 세션, 2.60.7)

### 11.1 막는 문제: pickle 저장
- **문제.** 사본을 `pickle.gz`로 저장하고, 같은 폴더의 `manifest.json`에 적힌 SHA-256과 맞으면 `pickle.load`로 열었다. 폴더를 쓸 수 있는 사람은 pickle과 manifest를 함께 바꿀 수 있으므로 해시는 보안 장치가 아니다. 공유 드라이브의 `V2_CACHE_DIR`, 남이 건넨 캐시 폴더, 복원한 백업에서 `V2_LOCAL_LISTS=all`이면 코드가 실행될 수 있었다(검토 중 무해한 탑재물로 재현). 기본(꺼짐)에서는 디스크를 읽기 전에 돌아가므로 닿지 않는다. 그러나 README와 NOTICES가 `=all`을 안내하므로 병합 전에 고쳤다.
- **고침.** gzip ECSV로 저장한다. 가림은 `serialize_method=data_mask`로 지키고, astropy의 안전한 YAML 로더로 읽으므로 읽기가 코드를 실행할 수 없다.
  - 받은 표는 ECSV로 쓴 뒤 다시 읽어 열·형·가림·값이 같은지 확인하고, 다르면 저장하지 않는다. VizieR 실물로는 이 환경에서 확인하지 못했으므로, 다르게 읽히는 열이 있으면 기능이 원격으로 돌아갈 뿐 틀린 답을 내지 않게 하려는 것이다.
  - 해시는 손상 확인용으로만 남겼다.
  - 대안인 pickle 유지 + 폴더 권한 확인은 Windows에서 쓸 수 없고 복사한 폴더를 막지 못해 버렸다.
- **시험.** 해시까지 맞춘 가짜 pickle을 심어도 실행되지 않는다. 가림·형·단위가 왕복 뒤에도 같다.

### 11.2 고친 것
- **실패 기억.** 받기 실패를 프로세스 사이에서도 600초 기억한다(`archive_cache.note_source`). 앱은 검색마다 프로세스를 새로 띄우므로, 프로세스 안의 기억만으로는 "10분 동안 다시 시도하지 않음"이 지켜지지 않았다.
- **동시 받기.** 한 목록은 잠금 파일로 한 프로세스만 받는다. 잠금은 쥔 동안 갱신한다(Codex 지적, PR #83). `archive_cache._FileLock`은 30초 동안 손대지 않으면 낡은 것으로 지워지는데, 다운로드는 미러를 넘나들며 그보다 오래 걸릴 수 있기 때문이다. 쥔 프로세스가 죽으면 30초 뒤 풀린다. 갱신하지 않으면 시험이 실패하는 것을 확인했다. 임시 파일은 `mkstemp`의 고유한 이름을 쓰고, manifest는 임시 파일에 쓴 뒤 이름을 바꾼다.
- **명령 표기.** 문서의 `--refresh/--status/--remove`를 실제 명령인 `refresh/status/remove`(위치 인자)로 고쳤다. `V2_LOCAL_LISTS_REFRESH=1`도 적었다.
- **잘못된 스위치 값.** `V2_LOCAL_LISTS=1/on/yes`는 켠 것처럼 읽히지만 지금까지는 조용히 `auto`(= 꺼짐)였다. 이제 오류로 멈춘다.
- **문서.** NOTICES의 빈 줄 누락(다음 문장이 목록 항목에 붙음)을 고쳤다. README 문구를 "기본 꺼짐, `=all`로 켬"으로 바꿨다. ALGORITHM의 `_r` 차이를 측정값 5×10⁻⁴′로 맞췄다.
