## 2. 과제 러

### 2.1 무엇을 만들고 왜 그렇게 만들었나

* **`measure_association.py`: 열 추가만.** `right_object = correct + rightly_alone`, `right_object_pct_of_expected`, `shifted_any_pct`(이동한 행 중 객체에 이동하지 않은 카탈로그의 행이 **하나라도** 있는 비율)를 맨 끝 열로 붙였다. 옛 열의 순서와 값은 그대로다(요약 도구의 앞 15열이 같음을 비교로 확인). 이유: 2.60.9~2.62.6의 모든 결과 표가 옛 열 위치를 읽고 있어 순서를 바꾸면 조용히 어긋난다.
* **새 재집계 도구 `right_object_recount.py`: 필드별 JSON의 합.** `measure_association.py`가 이미 필드마다 개수(`correct`, `rightly_alone`, `missed`, `shift_any` …)를 JSON으로 낸다. 분할(보정 9 / 확인 17, 보정 15 / 시험 11, 전체 26)은 필드 묶음일 뿐이라 다시 재지 않고 합만 바꾼다. 대안은 분할마다 측정을 다시 도는 것이었는데 Stage 1 결과가 같은 필드에서 같으므로 같은 숫자를 다시 만들 뿐이다. 분할이 둘인 이유: 2.61.8의 "+46 / +32"는 **보정 9 / 확인 17**(COSMOS 필드 1–9 / 10–26, `association_ambiguity`)이고, 2.60.9의 기준선은 **보정 15 / 시험 11**(`fields_split.csv`)이다. 두 분할을 섞으면 같은 이름의 숫자가 다른 필드의 값이 된다.
* **영역(필드) 부트스트랩 구간.** 2.60.9부터 쓴 독립 단위(필드)를 그대로 따랐다(2,000회, seed 1). 행 단위 구간은 같은 필드의 행이 서로 상관이라 너무 좁다.
* **분석 함수를 `compute()`로 분리**하고 합성 필드로 세 구조를 시험했다(재라벨은 이득이 아님, 새로 붙은 정답은 이득, `missed → rightly_alone`는 `right_object`만 봄). 도구가 표를 틀리게 내면 결론이 틀리기 때문이다.

## 4. 설계 이유 모음

| 선택 | 대안과 버린 이유 |
|---|---|
| 재집계는 필드별 JSON의 합(`right_object_recount.py`) | 분할마다 측정을 다시 돌림: 결과가 같고 불필요하다. 합이면 어떤 분할이든 즉시 나오고 분할 이름 혼동을 도구가 막는다. |
