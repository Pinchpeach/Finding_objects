# 작업 보고서 2026-11-28e — 동결 정답 목록을 커밋하는 워크플로 (2.62.8)

## 무엇을 했나

`v2 scientific cross validation`을 `freeze_truth = true`로 돌리면 정답 목록이 아티팩트 `frozen-truth-candidate`로만 올라간다. 이것을 `v2/Classifier/truth/fixed/`에 넣는 단계(`truth/README.md`의 2단계)를 워크플로 `v2_commit_frozen_truth.yml`과 스크립트 `.github/scripts/commit_frozen_truth.py`로 만들었다.

* 입력은 동결 실행의 run id와 아티팩트 이름이고, 선택으로 두 번째 동결 실행의 run id(`compare_run_id`)를 받는다.
* 받은 목록마다 빌더의 `verify`를 돌린다(파일 SHA-256, 클래스별 id 집합의 SHA-256, 모든 집합 status ok). 그리고 `list_sha256`을 계산한다.
* 두 목록을 주면 `list_sha256`이 같을 때만 복사한다. 다르면 어느 집합이 다른지 적고 실패한다. 아무것도 복사하지 않는다.
* 매니페스트와 매니페스트에 적힌 파일만 `fixed/`에 복사한다. `fixed/`는 통째로 바꾼다. 복사본을 다시 `verify`한다.
* **커버리지 기준선**(`fixed/baseline_coverage.json`, 동결 목록 위의 첫 정상 실행이 잰 클래스별 분류 비율)은 그 기준선의 `truth_list_sha256`이 들어오는 목록과 같으면 남긴다. 다르면 지운다. 같은 목록을 다시 커밋해도 회귀 감시가 사라지지 않게 하려는 것이다. 목록이 바뀌면 `aggregate_independent_truth.py`가 어차피 그 기준선을 불일치로 거부한다(Codex 검토).
* 실행한 가지(`github.ref_name`)에 커밋하고 `push_with_retry.sh`로 올린다. main에서 실행하면 첫 단계에서 실패한다.

## 왜 이렇게 했나

* **워크플로로 한 이유**: 이 클라우드 컨테이너는 아티팩트를 받을 수 없다(다운로드가 Azure blob 저장소로 넘어가고 프록시가 그 호스트를 거부한다). 사용자가 손으로 받아 넣을 수도 있지만, 워크플로로 하면 "동결 실행 → 아티팩트 → 확인 → 커밋"의 사슬이 run id와 로그로 남는다. 다시 동결할 때도 같은 경로를 쓴다.
* **두 실행 비교**: 빌더는 결정적이다(전체 표를 질의하고, 클래스마다 SHA-256 순서의 아래쪽 k개를 고른다). 이것을 가정하는 대신, 다른 시각(가능하면 다른 미러)의 두 동결 실행이 같은 목록을 내는지 커밋 전에 시험한다(검토 세션의 제안).
* **main 거부**: 동결 목록은 분류 검증의 기준이 바뀌는 일이라 PR 검토와 판 올림을 거쳐야 한다. 워크플로가 main에 직접 쓰지 않게 했다.
* **매니페스트 파일만 복사**: 아티팩트는 빌더의 작업 폴더 전체를 담으므로 목록이 아닌 파일이 섞일 수 있다.
* **버린 대안**:
  * (a) 사용자가 손으로 넣는 것: 재현 기록이 남지 않는다.
  * (b) 동결 실행이 곧바로 커밋하는 것: 동결과 커밋 사이에 확인과 비교의 단계가 없어진다.
